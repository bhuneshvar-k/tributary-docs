This guide takes you from a fresh install to your first copied subset. You set up two connections, preview a subset, and then copy it.

## Before you start

- Install Tributary. See [Installation](/installation).
- Have a **source** Postgres database to read from, such as production or a replica.
- Have a **target** Postgres database to write to, such as a local database. It can be empty, because Tributary creates missing tables.

<Tip>
  Use a read-only database role for the source. Tributary never writes to the source, but a read-only role adds a second layer of protection.
</Tip>

## Copy your first subset

<Steps>
  <Step title="Add your connections">
    Give each database a short name. You use these names on every command instead of full connection strings.

    ```bash
    tributary config set connections.prod.url  'postgres://readonly@prod-db:5432/app'
    tributary config set connections.local.url 'postgres://localhost:5432/app_dev'
    ```
  </Step>
  <Step title="Allow your target host">
    Tributary refuses to write to any host that isn't on your allowlist. The allowlist starts empty, which blocks every target.

    ```bash
    tributary config set allowlist localhost
    ```

    For several hosts, separate them with commas: `localhost,*.staging.internal`.
  </Step>
  <Step title="Preview the subset">
    `plan` computes the subset and shows how many rows each table contributes. It writes nothing.

    ```bash
    tributary plan -t users -w "email = 'admin@example.com'" --source prod
    ```

    - `-t users` is the **seed table**.
    - `-w "email = 'admin@example.com'"` is a SQL `WHERE` fragment that picks the seed rows.

    You see a table like this:

    ```text
    no schema file: following database foreign keys only (see tributary schema init)
    ┌──────────────────┬──────┬──────────────────────────────────────────────────┐
    │ table            │ rows │ via                                              │
    ├──────────────────┼──────┼──────────────────────────────────────────────────┤
    │ public.companies │ 1    │ public.users.company_id -> public.companies.id   │
    │ public.users     │ 1    │ seed                                             │
    │ public.orders    │ 12   │ public.orders.user_id -> public.users.id         │
    │ public.products  │ 7    │ public.order_items.product_id -> public.products.id │
    │ public.order_items │ 31 │ public.order_items.order_id -> public.orders.id  │
    └──────────────────┴──────┴──────────────────────────────────────────────────┘
    
    total: 52 rows across 5 tables
    ```

    The **via** column shows how Tributary reached each table.
  </Step>
  <Step title="Copy the subset">
    When the plan looks right, run `sync` with the same seed and a target:

    ```bash
    tributary sync -t users -w "email = 'admin@example.com'" --source prod --target local
    ```

    Tributary creates any missing tables on `local`, then loads the rows:

    ```text
    ┌────────────────────┬──────────┬────────────┬───────────┬────────┐
    │ table              │ upserted │ backfilled │ left null │ status │
    ├────────────────────┼──────────┼────────────┼───────────┼────────┤
    │ public.companies   │ 1        │ 0          │ 0         │ loaded │
    │ public.users       │ 1        │ 0          │ 0         │ loaded │
    │ ...                │          │            │           │        │
    └────────────────────┴──────────┴────────────┴───────────┴────────┘
    
    created 5 table(s) on target: public.companies, public.order_items, ...
    total: 52 rows upserted across 5 tables (run 3f9a1c0d2b7e4a61)
    ```
  </Step>
  <Step title="Run it again (optional)">
    Running the same `sync` again is safe. Rows already on the target are updated to match the source, and nothing is duplicated.
  </Step>
</Steps>

## More ways to pick seeds

Use several seeds in one run by repeating the `-t` and `-w` pair. Each `-t` pairs with the `-w` in the same position.

```bash
tributary sync \
  -t users -w "id = 42" \
  -t feature_flags -w true \
  --source prod --target local
```

`-w true` selects every row of that table. Use it for small lookup tables.

Tables outside the `public` schema use a `schema.table` name:

```bash
tributary plan -t billing.invoices -w "number = 'INV-1001'" --source prod
```

## Prefer plain language?

If you've set up an AI provider, describe what you want and Tributary builds the command:

```bash
tributary ai "copy the user admin@example.com and their orders" --source prod --target local
```

It shows the generated command and asks before it writes anything. See [Tributary AI](/tributary-ai).
