This guide walks you through installing Tributary and syncing your first subset from a source Postgres database to a target.

## Prerequisites

Before you begin, make sure you have:

- **Go 1.25+** (if installing via `go install`)
- **Docker** (if running integration tests)
- Access to two Postgres databases (source and target) — they can be the same instance with different database names

## Step 1: Install Tributary

Choose your preferred installation method:

<Tabs>
  <Tab title="Homebrew (Recommended)">
    ```bash
    brew tap bhuneshvar-k/tap
    brew trust bhuneshvar-k/tap
    brew install tributary
    ```

    <Note>
      `brew trust` is required once per machine for third-party taps. After that, `brew upgrade tributary` works automatically.
    </Note>
  </Tab>
  <Tab title="curl Installer">
    ```bash
    curl -sSL https://get.tributary.dev | bash
    ```

    With options:

    ```bash
    # Install specific version
    curl -sSL https://get.tributary.dev | bash -s -- --version v1.0.0
    
    # Install to custom directory
    curl -sSL https://get.tributary.dev | bash -s -- --to ~/.local/bin
    ```
  </Tab>
  <Tab title="Go Install">
    ```bash
    go install github.com/bhuneshvar-k/tributary/cmd/tributary@latest
    ```
  </Tab>
  <Tab title="Build from Source">
    ```bash
    git clone https://github.com/bhuneshvar-k/tributary.git
    cd tributary
    make build
    ./bin/tributary --version
    ```
  </Tab>
</Tabs>

Verify the installation:

```bash
tributary --version
# tributary version v1.0.0
```

## Step 2: Set Your DSN

Export your source database connection string:

```bash
export TRIBUTARY_DSN="postgres://user:password@localhost:5432/source_db?sslmode=disable"
```

<Warning>
  Always use `sslmode=require` or `sslmode=verify-full` in production environments. `sslmode=disable` is only for local development.
</Warning>

## Step 3: Inspect Your Schema

Run the `inspect` command to see your database structure:

```bash
tributary inspect --dsn "$TRIBUTARY_DSN"
```

This outputs a JSON document showing every table, its columns (with types and nullability), primary keys, and foreign keys.

## Step 4: Plan a Subset

Before syncing, preview what rows will be included:

```bash
tributary plan   --dsn "$TRIBUTARY_DSN"   --seed-table users   --seed-predicate "id = 42"
```

This shows per-table row counts for the referentially consistent subset rooted at `users.id = 42`.

## Step 5: Sync the Subset

Now copy the subset to your target database:

```bash
tributary sync run   --source-dsn "postgres://user:password@localhost:5432/source_db?sslmode=disable"   --target-dsn "postgres://user:password@localhost:5432/target_db?sslmode=disable"   --seed-table users   --seed-predicate "id = 42"
```

Tributary will:

1. Auto-create any missing tables in the target database
2. Load rows in FK-safe order
3. Use upsert semantics — safe to re-run

## What's Next?

<AccordionGroup>
  <Accordion title="Run it again (refresh)">
    Simply re-run the same `sync run` command. Upsert semantics mean existing rows get updated, new rows get inserted.

    ```bash
    tributary sync run --source-dsn ... --target-dsn ... --seed-table users --seed-predicate "id = 42"
    ```
  </Accordion>

  <Accordion title="Add custom relationships">
    If your database has relationships that aren't enforced by foreign keys (common in Rails/ActiveRecord apps), create a `tributary.schema.yaml` file.

    See [Schema Configuration](/schema-configuration) for details.
  </Accordion>

  <Accordion title="Sync a different user">
    Change the seed predicate to target a different row:

    ```bash
    tributary sync run       --source-dsn "$SOURCE_DSN"       --target-dsn "$TARGET_DSN"       --seed-table users       --seed-predicate "email = 'alice@example.com'"
    ```
  </Accordion>

  <Accordion title="Force a fresh reload">
    Use `--fresh` to wipe existing subset rows before reloading:

    ```bash
    tributary sync run --fresh --source-dsn ... --target-dsn ... --seed-table users --seed-predicate "id = 42"
    ```
  </Accordion>
</AccordionGroup>
