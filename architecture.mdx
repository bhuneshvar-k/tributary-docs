This page describes how Tributary is built, for contributors and for anyone who wants to know what happens under the hood. To _use_ Tributary, [How it works](/how-it-works) is enough.

## Repository layout

Tributary is a TypeScript monorepo managed with pnpm.

```text
tributary/
├── packages/
│   ├── core/          @bhuneshvar-k/tributary-core — the engine
│   │   ├── src/
│   │   └── test/      unit + integration tests (PGlite)
│   └── cli/           @bhuneshvar-k/tributary — the `tributary` command
│       ├── src/
│       └── test/
├── .github/workflows/ ci.yml, release.yml
├── biome.json         lint + format
└── vitest.config.ts
```

The CLI is a thin layer. It parses flags, resolves connection names and the schema file, prints results, and calls the core's `plan`, `sync`, `inspect`, and `schemaTemplate`. All database logic lives in `core`.

## Core modules

| Module | Responsibility |
| --- | --- |
| `catalog.ts` | Types for the introspected schema: `Table`, `Column`, `ForeignKey`, `Schema`. |
| `inspect.ts` | Reads tables, columns, primary keys, foreign keys, and enums from `information_schema` and `pg_catalog`. |
| `schema-file.ts` | Parses and validates schema files (YAML/JSON) into relations and cycle breaks. |
| `config.ts` | Shared types: `Seed`, `Relation`, `Traversal`, `ConfigError`. |
| `graph.ts` | Builds the table graph from foreign keys plus declared relations. Indexes edges both ways and finds cycles. |
| `closure.ts` | The walk: computes the subset from the seeds, applies traversal rules and cycle breaks. Decides which columns are deferred. |
| `order.ts` | Topologically sorts tables for loading. |
| `plan.ts` | `computeSubset` (inspect, graph, closure, order) and `plan`. |
| `ddl.ts` | Creates missing schemas, enums, tables, and foreign keys on the target. Checks existing tables are compatible. |
| `load.ts` | Batched upserts, backfills, and `--fresh` deletes. Explains constraint errors. |
| `state.ts` | Run IDs, row fingerprints, and checkpoints in the target's `_tributary` schema. |
| `guards.ts` | Target allowlist and the same-database check. |
| `db.ts` | Connections, transactions, read-only snapshots, and identifier quoting. |
| `sync.ts` | Orchestrates a sync from start to finish. |

## Key design decisions

### Values travel as text

The `pg` client is configured to return every value as Postgres's text output, with no JavaScript type parsing. Values are sent back to the target as text and parsed by the target's input functions. This avoids precision loss for `bigint`, `numeric`, and microsecond timestamps, and handles arrays, JSON, and `bytea` without special cases.

### Rows are identified by primary key

The walk keys every row by its primary-key values, so a row reached by several paths is stored once. This is why every table in the subset needs a primary key, and why upserts use `ON CONFLICT (primary key)`.

### Breadth-first walk with reach tracking

`computeClosure` runs a breadth-first search. Each row carries a **reach**: `downstream` or `parent`. Outgoing edges (to parents) are always followed. Incoming edges (to children) are followed only for downstream rows, or for every row under `--traversal full`. A row first seen as a parent and later reached downstream is expanded again.

Each step is one parameterized `SELECT * FROM table WHERE col = $1 ...`. The seed query is the only one that contains user SQL, and it runs with the extended protocol so it can only be a single statement.

### Cycles are broken, then backfilled

`graph.ts` finds strongly connected components so the walk knows which edges are cyclic. When a row would follow a cyclic edge, `breakEdge` either uses a configured `breakCycle`, throws under `--strict-cycles`, or breaks the edge automatically. A broken edge stays broken for the rest of the walk.

`deferredForeignKeys` then lists the real constraints that can't be satisfied row by row: self-references, broken edges, and ignored foreign keys. Those columns are written `NULL` during the upsert and restored in a final backfill pass, only where the referenced row is in the subset.

### Load order uses real constraints only

`tableOrder` runs Kahn's algorithm over the real foreign keys between subset tables, skipping self-references and deferred columns. Ties break alphabetically for deterministic output. Declared relations don't affect order, because the target doesn't enforce them.

### Checkpoints commit with the data

Each table's upsert and its checkpoint row commit in one transaction on the target. A crash can't leave a table loaded but unrecorded, or recorded but not loaded. The checkpoint stores a SHA-256 fingerprint of the table's rows, so a resume reloads any table whose source data changed.

### Batching

Upserts, backfills, and deletes are batched to at most 1,000 rows and about 60,000 bind parameters per statement, under Postgres's 65,535-parameter limit.

## Development

```bash
pnpm install
pnpm test        # unit + integration tests
pnpm typecheck
pnpm lint        # Biome
pnpm build
```

Integration tests run Postgres **in-process** with [PGlite](https://pglite.dev), so you don't need Docker or a local Postgres server.

## History

Tributary was first written in Go. That version is archived as `tributary-go`. The TypeScript rewrite keeps the same core idea and adds a reusable library package, a committed schema file format, checkpoints stored in the target, and a multi-provider AI command.
