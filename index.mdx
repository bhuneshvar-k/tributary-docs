Tributary is a command-line tool that extracts **referentially consistent subsets** from a Postgres database and loads them into a target Postgres instance.

It walks real foreign keys plus user-declared relationships, computes the closure of rows that must travel together, and loads that subset — maintaining full referential integrity in the target.

```text
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│  Source Postgres │ ───► │    Tributary    │ ───► │ Target Postgres │
│   (Production)  │      │  (CLI Tool)     │      │  (Dev/Staging)  │
└─────────────────┘      └─────────────────┘      └─────────────────┘
```

## Why Tributary?

Production databases grow fast. Copying the entire dataset to dev or staging is slow, expensive, and often impractical. But naively copying a few rows breaks foreign key constraints and leaves you with an unusable database.

Tributary solves this by computing the **referential closure** of a seed query — it follows every foreign key relationship to determine exactly which rows must travel together, then loads them in the correct order.

## How It Works

Tributary operates in four phases:

1. **Inspect** — Reads the source database's schema from `pg_catalog`: tables, columns, primary keys, foreign keys, and enum types.
2. **Graph Build** — Merges discovered FK constraints with user-declared relationships (from `tributary.schema.yaml`) into a single relationship graph. Detects cycles.
3. **Closure Walk** — Starting from seed rows (matching your WHERE predicate), walks the graph to compute every row that must travel together for referential validity.
4. **Load** — Creates missing target tables, then loads rows in FK-safe order using upsert semantics (`INSERT ... ON CONFLICT DO UPDATE`).

## Quick Example

```bash
# Inspect your schema
tributary inspect --dsn "postgres://user:pass@localhost:5432/prod"

# Plan a subset
tributary plan --seed-table users --seed-predicate "id = 42"

# Sync it to your dev database
tributary sync run --source-dsn "postgres://user:pass@localhost:5432/prod" --target-dsn "postgres://user:pass@localhost:5432/dev" --seed-table users --seed-predicate "id = 42"
```
