Tributary ships with an MCP (Model Context Protocol) server that lets AI assistants inspect databases, preview subsets, and run syncs directly — no CLI shelling required.

## Setup

The MCP server binary `tributary-mcp-server` is included in every release. Add it to your AI assistant's MCP configuration:

<Tabs>
  <Tab title="OpenCode">
    Add to `opencode.json`:

    ```json
    {
      "mcp": {
        "servers": {
          "tributary": {
            "command": ["tributary-mcp-server"]
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Desktop">
    Add to `claude_desktop_config.json`:

    ```json
    {
      "mcpServers": {
        "tributary": {
          "command": "tributary-mcp-server"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Cursor / Windsurf">
    Add to your MCP config:

    ```json
    {
      "mcpServers": {
    ```

## Available Tools

### `tributary_version`

Returns the Tributary version, commit hash, and build date.

**Input:** None

**Output:**

```json
{
  "version": "v1.0.0",
  "commit": "abc1234",
  "date": "2025-01-15T10:30:00Z"
}
```

---

### `tributary_check_connection`

Test connectivity to a Postgres database and return the server version. Useful for verifying DSN strings before running sync.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `dsn` | string | Postgres connection string |

**Output:**

```json
{
  "status": "connected",
  "version": "PostgreSQL 16.1 on x86_64-pc-linux-gnu",
  "uptime": "3 days 14:22:05.123456"
}
```

---

### `tributary_inspect_schema`

Inspect a Postgres database schema: tables, columns, types, primary keys, and foreign keys. Returns structured JSON useful for understanding what tables exist and how they relate.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `dsn` | string | Postgres connection string |

**Output:** Full schema JSON matching the `tributary inspect` CLI output — tables, columns, primary keys, foreign keys, and enum types.

---

### `tributary_list_tables`

Quick table overview with column counts and primary keys. Lighter-weight alternative to `inspect_schema`.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `dsn` | string | Postgres connection string |

**Output:**

```json
{
  "total": 5,
  "tables": [
    {
      "name": "users",
      "schema": "public",
      "columns": 4,
      "primary_key": ["id"],
      "foreign_keys": 0
    }
  ]
}
```

---

### `tributary_validate_config`

Validate a `tributary.schema.yaml` file. Returns parsed relationships and any validation errors.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `config_file` | string | Path to the tributary schema YAML file |

**Output:**

```json
{
  "status": "valid",
  "file": "tributary.schema.yaml",
  "relations": [...]
}
```

---

### `tributary_subset_preview`

Preview which tables and rows would be included in a subset sync **without actually loading anything**. Returns the closure (table → row keys), FK graph, and load order.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `dsn` | string | Postgres connection string for the SOURCE database |
| `seed_table` | string | Fully qualified seed table (e.g. `public.users`) |
| `seed_predicate` | string | SQL WHERE clause without WHERE keyword (e.g. `email = 'admin@example.com'`) |
| `config_file` | string | _Optional._ Path to a tributary schema file |

**Output:**

```json
{
  "seed_table": "public.users",
  "seed_predicate": "id = 42",
  "total_tables": 4,
  "total_rows": 55,
  "load_order": ["public.users", "public.orders", "public.order_items", "public.products"],
  "tables": [
    { "table": "public.users", "row_keys": ["id=42"], "row_count": 1 },
    { "table": "public.orders", "row_keys": ["..."], "row_count": 12 }
  ]
}
```

---

### `tributary_subset_sync`

Run a full subset sync from source to target Postgres. Creates missing tables, loads data with upsert semantics. Use `tributary_subset_preview` first to verify what will be synced.

**Input:**

| Parameter | Type | Description |
| --- | --- | --- |
| `source_dsn` | string | Postgres connection string for the SOURCE database |
| `target_dsn` | string | Postgres connection string for the TARGET database |
| `seed_table` | string | Fully qualified seed table (e.g. `public.users`) |
| `seed_predicate` | string | SQL WHERE clause without WHERE keyword |
| `fresh` | boolean | _Optional._ Delete existing subset rows from target before reload (default: `false`) |
| `config_file` | string | _Optional._ Path to a tributary schema file |
| `batch_size` | integer | _Optional._ Rows per batch for backfill/delete (default: `500`) |

**Output:**

```json
{
  "status": "completed",
  "total_rows": 55,
  "tables": [
    { "table": "public.users", "rows_copied": 1, "rows_backfilled": 0, "skipped_resumed": false },
    { "table": "public.orders", "rows_copied": 12, "rows_backfilled": 0, "skipped_resumed": false }
  ]
}
```

## Example: AI-Driven Subset Workflow

With the MCP server connected, you can ask your AI assistant:

> "Inspect my production database at postgres://prod:5432/app, preview the subset for user id=42, then sync it to my dev database at postgres://localhost:5432/dev"

The AI will call the MCP tools in sequence — no manual CLI needed.

### Conversation Flow

1. **AI calls** `tributary_check_connection` with the source DSN → confirms connectivity
2. **AI calls** `tributary_inspect_schema` with the source DSN → understands the schema
3. **AI calls** `tributary_subset_preview` with seed table and predicate → shows you what will be synced
4. **You confirm** the preview looks correct
5. **AI calls** `tributary_subset_sync` with source and target DSNs → performs the sync
