Tributary keeps machine-specific settings in a local config file: named connections, the target allowlist, and AI provider settings. You manage it with `tributary config`.

<Note>
  These settings describe _your machine_, not your database. Relationships between tables go in the [schema file](/schema-configuration), which you can commit to your repository.
</Note>

## Quick setup

```bash
# Connections
tributary config set connections.prod.url  'postgres://readonly@prod-db:5432/app'
tributary config set connections.local.url 'postgres://localhost:5432/app_dev'

# Hosts sync may write to
tributary config set allowlist localhost

# AI provider (optional, only for tributary ai)
tributary config set ai.provider anthropic
tributary config set ai.apiKey   'sk-ant-...'
```

## Settings

### Connections

<ParamField path="connections.<name>.url" type="string" required>
  A Postgres connection URL. `<name>` is the short name you pass to `--source` and `--target`. Names can contain letters, digits, `_`, and `-`.

  ```bash
  tributary config set connections.staging.url 'postgres://app@staging-db:5432/app?sslmode=require'
  ```
</ParamField>

Any standard Postgres URL works, including query parameters such as `sslmode`. Use a Unix socket with `postgres:///app?host=/var/run/postgresql`.

If a command names a connection that doesn't exist, Tributary lists the ones it knows:

```text
error: no connection named "prd" (known: prod, local); add it with: tributary config set connections.prd.url <postgres-url>
```

### Allowlist

<ParamField path="allowlist" default="[] (deny all)" type="string[]">
  Hosts that `sync` may write to, set as a comma-separated list. Entries are exact host names, Unix socket directories, or `*.suffix` wildcards.

  ```bash
  tributary config set allowlist 'localhost,127.0.0.1,*.staging.internal'
  ```
</ParamField>

Setting `allowlist` replaces the whole list. An empty list blocks every target. See [Safety](/safety#writes-need-an-allowlist) for the matching rules.

### AI provider

These settings only matter for [`tributary ai`](/tributary-ai).

<ParamField path="ai.provider" default="anthropic" type="string">
  One of `anthropic`, `openai`, `google`, `openrouter`, or `opencode`. Any other value is rejected.
</ParamField>

<ParamField path="ai.model" type="string">
  The model ID. Optional for `anthropic`, `openai`, and `google`, which have defaults. Required for `openrouter` and `opencode`.
</ParamField>

<ParamField path="ai.apiKey" type="string">
  The provider's API key. If unset, Tributary uses the provider's usual environment variable, such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`.
</ParamField>

<ParamField path="ai.baseUrl" type="string">
  A custom API endpoint. Required for `opencode`. Optional for the others, for example to use a proxy.
</ParamField>

## Managing settings

| Command | What it does |
| --- | --- |
| `tributary config set <key> <value>` | Set a value. |
| `tributary config get <key>` | Print one value. Prints nothing if it isn't set. |
| `tributary config unset <key>` | Remove a value. |
| `tributary config list` | Print every setting as JSON, **secrets included and unmasked**. |
| `tributary config path` | Print the config file's location. |

`get` also accepts a parent key. For example, `tributary config get connections` prints every connection as JSON. `set` and `unset` only accept the full keys listed above.

```bash
tributary config get connections.prod.url
tributary config unset connections.old.url
```

An unknown key is rejected with the list of valid ones:

```text
error: unknown config key "conections.prod.url"; valid keys: connections.<name>.url, allowlist, ai.provider, ai.model | ai.apiKey | ai.baseUrl
```

## Where settings are stored

The config is a JSON file named `config.json`. Its directory is chosen in this order:

| Condition | Directory |
| --- | --- |
| `TRIBUTARY_CONFIG_DIR` is set | `$TRIBUTARY_CONFIG_DIR` |
| Windows | `%APPDATA%\tributary` |
| `XDG_CONFIG_HOME` is set to an absolute path | `$XDG_CONFIG_HOME/tributary` |
| Otherwise (macOS and Linux) | `~/.config/tributary` |

Run `tributary config path` to see the exact file.

The file looks like this:

```json ~/.config/tributary/config.json
{
  "connections": {
    "prod": { "url": "postgres://readonly@prod-db:5432/app" },
    "local": { "url": "postgres://localhost:5432/app_dev" }
  },
  "allowlist": ["localhost"],
  "ai": {
    "provider": "anthropic",
    "apiKey": "sk-ant-..."
  }
}
```

<Tip>
  Use `TRIBUTARY_CONFIG_DIR` to keep separate configs, for example one per project or one for CI:

  ```bash
  TRIBUTARY_CONFIG_DIR=./.tributary tributary config set allowlist localhost
  ```

  If you put it inside a repository, add it to `.gitignore`. It contains secrets.
</Tip>

### Security

The file stores connection strings and API keys in **plaintext**. On macOS and Linux, Tributary keeps the directory at mode `0700` and the file at `0600`. Keep the file off shared machines and out of backups you don't control.

### Migrating from versions before 0.1.0 on macOS

Before version 0.1.0, macOS settings lived in `~/Library/Preferences/tributary`. The first time 0.1.0 or later runs, it moves that file to `~/.config/tributary/config.json` automatically, unless a new file already exists there.
