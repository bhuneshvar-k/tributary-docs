Every Tributary command and flag. Run `tributary --help` or `tributary <command> --help` for the same information in your terminal.

## Overview

| Command | What it does | Writes to |
| --- | --- | --- |
| [`plan`](#plan) | Computes the subset and reports row counts per table. | Nothing |
| [`sync`](#sync) | Copies the subset from source to target. | Target |
| [`inspect`](#inspect) | Prints the source schema as JSON. | Nothing |
| [`schema init`](#schema-init) | Writes a starting schema file. | A local file |
| [`schema validate`](#schema-validate) | Checks a schema file. | Nothing |
| [`config`](#config) | Manages local settings. | The local config file |
| [`ai`](#ai) | Turns a plain-language request into a command. | Target, after you confirm |

### Global flags

| Flag | Description |
| --- | --- |
| `-V, --version` | Print the version. |
| `-h, --help` | Print help for Tributary or a command. |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Any error, including invalid flags. The message is printed to stderr, prefixed with `error:`. |

### Output streams

Results go to **stdout**. Notes such as `using schema ./schema.yaml`, warnings, and errors go to **stderr**. This means `--json` output can be piped safely:

```bash
tributary plan -t users -w "id = 42" --source prod --json | jq '.totalRows'
```

## plan

Computes the subset and reports how many rows each table contributes. It never writes anything.

```bash
tributary plan --source <name> -t <table> -w <sql> [-t <table> -w <sql> ...] [options]
```

| Flag | Description |
| --- | --- |
| `-s, --source <name>` | **Required.** Source connection name. |
| `-t, --seed-table <table>` | Seed table, such as `users` or `billing.invoices`. Repeatable. |
| `-w, --where <sql>` | SQL `WHERE` fragment for the `--seed-table` in the same position, such as `"id = 42"`. Repeatable. |
| `--schema <file>` | Schema file. Default: `./schema.yaml`, `./schema.yml`, or `./schema.json`, whichever exists first. |
| `--traversal <mode>` | `downstream` (default) or `full`. See [Traversal modes](/how-it-works#traversal-modes). |
| `--strict-cycles` | Fail on a foreign key cycle with no `breakCycle` entry, instead of breaking it automatically. |
| `--json` | Print the result as JSON. |

You need at least one seed, and every `-t` needs a matching `-w`.

<Tabs>
  <Tab title="Examples">
    ```bash
    # One seed
    tributary plan -t users -w "email = 'admin@example.com'" --source prod
    
    # Two seeds
    tributary plan -t users -w "id = 42" -t feature_flags -w true --source prod
    
    # Table in another schema, full traversal
    tributary plan -t billing.invoices -w "id = 7" --traversal full --source prod
    
    # Explicit schema file, fail on undeclared cycles
    tributary plan -t users -w "id = 42" --schema config/schema.yaml --strict-cycles --source prod
    ```
  </Tab>
  <Tab title="JSON output">
    ```json
    {
      "tables": [
        { "table": "public.users", "rows": 1, "via": "seed" },
        { "table": "public.orders", "rows": 12, "via": "public.orders.user_id -> public.users.id" }
      ],
      "totalRows": 13,
      "breaks": [],
      "warnings": []
    }
    ```

    A table whose cycle was broken also has `"break": { "table": "...", "column": "...", "auto": true }`.
  </Tab>
</Tabs>

## sync

Copies the subset from the source into the target. It creates missing tables and upserts rows, so it's safe to run again.

```bash
tributary sync --source <name> --target <name> -t <table> -w <sql> [options]
```

Takes every [`plan`](#plan) flag, plus:

| Flag | Description |
| --- | --- |
| `-T, --target <name>` | **Required.** Target connection name. Its host must be on the [allowlist](/configuration#allowlist). |
| `--fresh` | Delete the subset's rows from the target first, and don't resume an earlier run. |
| `--no-create-schema` | Fail instead of creating missing target tables. |

<Note>
  `-s` is `--source` and `-T` (capital) is `--target`. `-t` (lowercase) is `--seed-table`.
</Note>

<Tabs>
  <Tab title="Examples">
    ```bash
    # Copy one user and their data
    tributary sync -t users -w "id = 42" --source prod --target local
    
    # Reset those rows on the target to match the source
    tributary sync -t users -w "id = 42" --source prod --target local --fresh
    
    # Target schema must come from migrations
    tributary sync -t users -w "id = 42" --source prod --target local --no-create-schema
    ```
  </Tab>
  <Tab title="Output">
    ```text
    ┌──────────────────┬──────────┬────────────┬───────────┬──────────────────────────┐
    │ table            │ upserted │ backfilled │ left null │ status                   │
    ├──────────────────┼──────────┼────────────┼───────────┼──────────────────────────┤
    │ public.companies │ 1        │ 0          │ 0         │ loaded                   │
    │ public.users     │ 1        │ 0          │ 0         │ already loaded (resumed) │
    │ public.employees │ 4        │ 3          │ 1         │ loaded                   │
    └──────────────────┴──────────┴────────────┴───────────┴──────────────────────────┘
    
    total: 5 rows upserted across 3 tables (run 3f9a1c0d2b7e4a61)
    ```

    See [Load order and deferred columns](/reruns-and-resume#load-order-and-deferred-columns) for what each column means.
  </Tab>
  <Tab title="JSON output">
    ```json
    {
      "runId": "3f9a1c0d2b7e4a61",
      "tables": [
        {
          "table": "public.users",
          "rowsUpserted": 1,
          "rowsBackfilled": 0,
          "rowsLeftNull": 0,
          "resumed": false
        }
      ],
      "totalRows": 1,
      "schema": {
        "typesCreated": [],
        "tablesCreated": ["public.users"],
        "constraintsCreated": [],
        "warnings": []
      },
      "breaks": [],
      "warnings": []
    }
    ```
  </Tab>
</Tabs>

Before writing, `sync` checks that the target host is allowlisted and that source and target aren't the same database. See [Safety](/safety).

## inspect

Prints the source schema as JSON: tables, columns, primary keys, foreign keys, and enum types.

```bash
tributary inspect --source <name>
```

| Flag | Description |
| --- | --- |
| `-s, --source <name>` | **Required.** Source connection name. |

```json
{
  "tables": [
    {
      "schema": "public",
      "name": "orders",
      "columns": [
        { "name": "id", "type": "bigint", "nullable": false, "udtSchema": "pg_catalog", "udtName": "int8", "sqlType": "bigint" },
        { "name": "user_id", "type": "bigint", "nullable": true, "udtSchema": "pg_catalog", "udtName": "int8", "sqlType": "bigint" }
      ],
      "primaryKey": ["id"],
      "foreignKeys": [
        {
          "constraintName": "orders_user_id_fkey",
          "fromTable": "public.orders",
          "fromColumns": ["user_id"],
          "toTable": "public.users",
          "toColumns": ["id"]
        }
      ]
    }
  ],
  "enums": { "public.order_status": ["pending", "paid", "shipped"] }
}
```

System schemas and Tributary's own `_tributary` schema are left out.

## schema init

Writes a starting schema file from the source database. Guessed references are written as comments for you to review.

```bash
tributary schema init --source <name> [options]
```

| Flag | Description |
| --- | --- |
| `-s, --source <name>` | **Required.** Source connection name. |
| `-o, --output <file>` | Where to write it. Default: `./schema.yaml`. |
| `--format <format>` | `yaml` (default) or `json`. JSON can't hold comments, so it only lists the tables. |
| `--force` | Overwrite an existing file. |

```text
$ tributary schema init --source prod
wrote ./schema.yaml: 42 tables, 17 guessed references to review
```

See [Schema file](/schema-configuration#create-a-schema-file).

## schema validate

Checks a schema file's format and, with `--source`, that its tables and columns exist in the database. Exits non-zero on any problem.

```bash
tributary schema validate [--schema <file>] [--source <name>]
```

| Flag | Description |
| --- | --- |
| `--schema <file>` | Schema file. Default: `./schema.yaml`, `./schema.yml`, or `./schema.json`. |
| `-s, --source <name>` | Also check against this connection's database. |

```text
$ tributary schema validate --source prod
./schema.yaml: valid
```

## config

Manages local settings: connections, the allowlist, and AI provider settings. See [Configuration](/configuration).

| Command | Description |
| --- | --- |
| `tributary config set <key> <value>` | Set a value. `allowlist` takes a comma-separated list. |
| `tributary config get <key>` | Print a value. |
| `tributary config unset <key>` | Remove a value. |
| `tributary config list` | Print every setting as JSON, secrets included, unmasked. |
| `tributary config path` | Print where settings are stored. |

Valid keys:

| Key | Example value |
| --- | --- |
| `connections.<name>.url` | `postgres://user@host:5432/db` |
| `allowlist` | `localhost,*.staging.internal` |
| `ai.provider` | `anthropic`, `openai`, `google`, `openrouter`, `opencode` |
| `ai.model` | `claude-sonnet-5-5` |
| `ai.apiKey` | `sk-ant-...` |
| `ai.baseUrl` | `http://localhost:11434/v1` |

## ai

Describe what you want in plain language. Tributary generates the command, shows it, and runs it.

```bash
tributary ai <request...> --source <name> [options]
```

| Flag | Description |
| --- | --- |
| `-s, --source <name>` | **Required.** Source connection name. |
| `-T, --target <name>` | Target connection name, for a generated `sync`. |
| `--schema <file>` | Schema file passed to the generated command. |
| `-y, --yes` | Run a generated `sync` without asking. |
| `--dry-run` | Only show the generated command. |

```bash
tributary ai "how many rows come with order 1001?" --source prod
tributary ai "copy the user admin@example.com and their orders" --source prod --target local
tributary ai "copy customer acme" --source prod --target local --dry-run
```

See [Tributary AI](/tributary-ai).
