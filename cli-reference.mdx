## `tributary inspect`

Prints source schema metadata as JSON. Use this to understand your database structure before planning a subset.

### Usage

```bash
tributary inspect --dsn "$TRIBUTARY_DSN"
```

### Flags

| Flag | Description | Required |
| --- | --- | --- |
| `--dsn` | Database connection string (or env `TRIBUTARY_DSN`) | Yes |

### Output

The output is a JSON document containing:

- **Tables** — Every user table in the database
- **Columns** — Column name, data type, nullability, length/precision/scale, and UDT name for custom types
- **Primary Keys** — Primary key columns per table (in declaration order)
- **Foreign Keys** — Every FK constraint with from/to table and column pairs (supports composite keys)
- **Enums** — Every custom enum type with its labels in declaration order

### Example

```bash
tributary inspect --dsn "postgres://user:pass@localhost:5432/mydb?sslmode=disable"
```

<Accordion title="Example Output">
  ```json
  {
    "tables": [
      {
        "schema": "public",
        "name": "users",
        "columns": [
          { "name": "id", "type": "integer", "is_nullable": false },
          { "name": "email", "type": "character varying", "is_nullable": false, "char_max_length": 255 }
        ],
        "primary_key": ["id"],
        "foreign_keys": []
      }
    ],
    "enums": {
      "status": ["active", "inactive", "pending"]
    }
  }
  ```
</Accordion>

## `tributary plan`

Computes a referentially consistent subset from a seed table and predicate. Shows per-table row counts without actually loading data.

### Usage

```bash
tributary plan \
  --dsn "$TRIBUTARY_DSN" \
  --seed-table users \
  --seed-predicate "id = 42"
```

### Flags

| Flag | Description | Required | Default |
| --- | --- | --- | --- |
| `--dsn` | Database connection string (or env `TRIBUTARY_DSN`) | Yes | — |
| `--seed-table` | Starting table for subset | Yes | — |
| `--seed-predicate` | SQL WHERE fragment to select seed rows | Yes | — |
| `--schema-file` | Path to schema relations file | No | — |
| `--strict-cycles` | Fail instead of auto-breaking cycles | No | `false` |
| `--include-upstream` | Enable full bidirectional fan-out | No | `false` |
| `--format` | Output format: `text` or `json` | No | `text` |

### Behavior

- Default mode is **downstream-only**: required parent rows are included but don't fan out to all siblings
- `--include-upstream` enables full fan-out from any discovered row
- `--seed-predicate` is a raw SQL `WHERE` fragment — not sanitized against injection (admin-tool trust model)

### Example

```bash
tributary plan \
  --dsn "postgres://user:pass@localhost:5432/prod?sslmode=disable" \
  --seed-table public.users \
  --seed-predicate "id = 42" \
  --schema-file tributary.schema.yaml
```

<Accordion title="Example Output">
  ```text
  Subset Plan
  ═══════════
  
  Seed: public.users WHERE id = 42
  Mode: downstream-only
  
  Table                     Rows
  ───────────────────────── ────
  public.users                 1
  public.orders               12
  public.order_items          34
  public.products              8
  
  Total: 55 rows across 4 tables
  ```
</Accordion>

## `tributary sync run`

Executes a one-shot subset copy from source to target. This is the main command for actually moving data.

### Usage

```bash
tributary sync run \
  --source-dsn "$SOURCE_DSN" \
  --target-dsn "$TARGET_DSN" \
  --seed-table users \
  --seed-predicate "id = 42"
```

### Flags

| Flag | Description | Required | Default |
| --- | --- | --- | --- |
| `--source-dsn` | Source database connection (or env `TRIBUTARY_SOURCE_DSN`) | Yes | — |
| `--target-dsn` | Target database connection (or env `TRIBUTARY_TARGET_DSN`) | Yes | — |
| `--seed-table` | Starting table for subset | Yes | — |
| `--seed-predicate` | SQL WHERE fragment to select seed rows | Yes | — |
| `--schema-file` | Path to schema relations file | No | — |
| `--strict-cycles` | Fail instead of auto-breaking cycles | No | `false` |
| `--include-upstream` | Enable full bidirectional fan-out | No | `false` |
| `--fresh` | Force cleanup before reload | No | `false` |
| `--no-create-schema` | Skip auto-creating target tables | No | `false` |
| `--state-db` | Path to checkpoint database | No | `.tributary/state.db` |
| `--no-resume` | Don't resume from checkpoints | No | `false` |
| `--format` | Output format: `text` or `json` | No | `text` |

### Behavior

- Default write mode is **upsert** (`INSERT ... ON CONFLICT DO UPDATE`)
- Re-running with the same scope is safe and expected
- `--fresh` performs subset-scoped cleanup before reload
- Missing target tables are auto-created by default
- Checkpointing in local SQLite for crash resume

### What Gets Created on the Target

When auto-create is enabled (default), Tributary creates missing target tables with:

- Columns + data types
- `NOT NULL` constraints
- `PRIMARY KEY` constraints
- Real foreign keys
- Enum type definitions

**Not covered:** Defaults, sequences/identity, check constraints, indexes beyond PK, triggers, views, non-enum custom types.

## `tributary ai`

Natural language interface — describe what you want in plain English and Tributary generates and runs the command.

### Usage

```bash
tributary ai "sync user admin@example.com"
```

### Setup (one-time)

```bash
# Pick a provider (claude, openai, gemini, openrouter, opencode)
tributary config set ai.provider claude

# Set your API key
tributary config set ai.api_key "sk-ant-your-key-here"

# (Optional) Set your DSN so the AI knows your schema
tributary config set dsn "postgres://user:pass@localhost:5432/mydb?sslmode=disable"
```

### Flags

| Flag | Description | Required | Default |
| --- | --- | --- | --- |
| `--dry-run` | Show the generated command without executing it | No | `false` |
| `--auto` | Skip confirmation prompt and execute immediately | No | `false` |
| `--provider` | Override AI provider for this invocation | No | — |
| `--model` | Override the AI model for this invocation | No | — |
| `--max-tokens` | Override max response tokens | No | `0` |
| `--format` | Output format: `text` or `json` | No | `text` |

### Examples

```bash
# Basic usage — AI translates your words into a tributary command
tributary ai "sync user admin@example.com"
tributary ai "plan a subset for all active users"
tributary ai "show me the schema for the orders table"

# Preview what the AI would do (no execution)
tributary ai --dry-run "sync all orders from last 7 days"

# Skip confirmation prompt
tributary ai --auto "subset users where team = 'marketing'"

# Override provider/model per invocation
tributary ai --provider openai "sync user 42"
tributary ai --provider gemini --model gemini-2.0-flash "plan orders"

# JSON output (for scripting)
tributary ai --format json "sync user admin@example.com"
```

### How It Works

1. **Schema load** — If a DSN is configured, Tributary inspects your database schema (tables, columns, foreign keys) and sends that metadata as context to the AI
2. **AI call** — Your prompt + schema context goes to the configured provider
3. **Parse** — The AI's JSON response is parsed into a structured command
4. **Preview** — The command, explanation, and any warnings are displayed
5. **Execute** — Unless `--dry-run`, the command runs after confirmation (or immediately with `--auto`)

### Supported Providers

| Provider | Default Model |
| --- | --- |
| `claude` | `claude-sonnet-4-20250514` |
| `openai` | `gpt-4o` |
| `gemini` | `gemini-2.0-flash` |
| `openrouter` | `anthropic/claude-sonnet-4-20250514` |
| `opencode` | `claude-sonnet-4-20250514` |

<Note>
  The AI feature requires an internet connection and a valid API key. It is completely optional — all other Tributary commands work offline.
</Note>

## `tributary config`

Manage user-level configuration stored in `~/.tributary/config.yaml`.

### Usage

```bash
tributary config <subcommand>
```

### Subcommands

| Subcommand | Description |
| --- | --- |
| `set <key> <value>` | Set a config value |
| `get <key>` | Get a config value |
| `list` | List all config values |
| `unset <key>` | Remove a config value |
| `path` | Print the config file path |

### Precedence

Config values are used as fallbacks when CLI flags and environment variables are not set:

**CLI flags > Environment variables > Config file**

The config file is optional — Tributary works without it.

### Available Keys

| Key | Description |
| --- | --- |
| `dsn` | Default Postgres connection string (inspect, plan) |
| `source_dsn` | Default source Postgres connection string (sync run) |
| `target_dsn` | Default target Postgres connection string (sync run) |
| `seed_table` | Default seed table name |
| `seed_predicate` | Default seed predicate (raw SQL WHERE fragment) |
| `schema_file` | Default path to tributary.schema.yaml |
| `ai.provider` | AI provider: `claude`, `openai`, `gemini`, `openrouter`, or `opencode` |
| `ai.api_key` | API key for the AI provider (stored with 0600 permissions) |
| `ai.model` | AI model override (empty = provider default) |
| `ai.base_url` | Custom AI API endpoint (empty = provider default) |

### Examples

```bash
# Set your database connection
tributary config set dsn "postgres://user:pass@localhost:5432/mydb?sslmode=disable"

# Set source and target for sync
tributary config set source_dsn "postgres://user:pass@localhost:5432/prod"
tributary config set target_dsn "postgres://user:pass@localhost:5432/dev"

# Set default seed parameters
tributary config set seed_table users
tributary config set seed_predicate "id = 42"

# Configure AI
tributary config set ai.provider claude
tributary config set ai.api_key "sk-ant-your-key-here"

# View all config
tributary config list

# Get a specific value
tributary config get dsn
```

### Security

- Config file is written with `0600` permissions (owner read/write only)
- DSN strings may contain passwords — the file is not world-readable
- API keys are stored in the same file with the same protections

## `tributary completion`

Generates shell autocompletion scripts for bash, zsh, fish, and PowerShell.

### Usage

```bash
tributary completion [shell]
```

### Shells

| Shell | Command |
| --- | --- |
| bash | `tributary completion bash` |
| zsh | `tributary completion zsh` |
| fish | `tributary completion fish` |
| powershell | `tributary completion powershell` |

### Install

**Bash:**

```bash
tributary completion bash > /etc/bash_completion.d/tributary
# Or for current session:
source <(tributary completion bash)
```

**Zsh:**

```bash
tributary completion zsh > "${fpath[1]}/_tributary"
# Or for current session:
source <(tributary completion zsh)
```

**Fish:**

```bash
tributary completion fish > ~/.config/fish/completions/tributary.fish
```

**PowerShell:**

```powershell
tributary completion powershell > tributary.ps1
. .\tributary.ps1
```

## DSN Format

Postgres connection strings follow this format:

```text
postgres://username:password@hostname:port/database?sslmode=require
```

### Common SSL Modes

| Mode | Description |
| --- | --- |
| `disable` | No SSL (local development only) |
| `require` | SSL required, no certificate verification |
| `verify-ca` | SSL required, verify server certificate |
| `verify-full` | SSL required, verify server certificate and hostname |
